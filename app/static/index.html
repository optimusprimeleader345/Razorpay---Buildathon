Frequently Asked Questions

Everything you need to know about Bounded Recovery's FSM state machine and hybrid AI safety architecture.

How does the dual attempt budget system operate? +
Bounded Recovery separates retries into two independent budgets: Customer-fault attempts (capped at 3, e.g., INSUFFICIENT_FUNDS or CARD_DECLINED) and Infrastructure-fault attempts (capped at 5, e.g., NETWORK_ERROR). A customer fault retry does not consume the infrastructure budget, and vice versa.
What happens when Anthropic Claude confidence is below 0.70? +
When the AI decision layer returns a confidence score below the defined threshold (0.70) or fails due to network/parsing errors, Bounded Recovery gracefully falls back to deterministic rule-based evaluation. The action is dispatched and audited with decision_source: "rule_based_fallback".
How are double-charges prevented during rapid retry calls? +
Every retry execution requires a mandatory Idempotency-Key header. Bounded Recovery locks charge processing and caches completed attempt payloads. If a duplicate retry call arrives with the same key, Bounded Recovery returns the cached response instantly without mutating counters or re-executing gateway calls.
What is the Safety Override layer? +
If the LLM recommends retrying a charge that has already reached its attempt budget limit (e.g. 3/3 customer attempts), Bounded Recovery's deterministic rule engine intercepts and overrides the recommendation, enforcing ESCALATED state and recording a safety_override audit event.
